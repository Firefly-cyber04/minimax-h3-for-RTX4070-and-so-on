# 部署说明（本机实测版）

> 机器：RTX 4070 Laptop · 8GB VRAM · 16GB 单通道 DDR5-5600 · Windows 11
> 目标：在官方最低配（48GB+ 显存）之外，用**量化 + CPU 卸载**把 H3-Image 跑起来。

---

## 1. 版本组合（缺一不可）

| 组件 | 版本 | 为什么必须是这个 |
|---|---|---|
| ComfyUI | **v0.45.0**（从 0.44.2 升级） | H3-Image 的 DiT / 采样器 / 条件节点是这版才进核心的 |
| ComfyUI-GGUF | `ff8d486`（2026-11-13） | 支持 `minimax` 架构，并把 GGUF 内嵌的 `config` 元数据透传给核心 |
| 模板包 | comfyui-workflow-templates 0.11.105 | ≥ 0.11.104 |
| Python 依赖 | comfy-kitchen 0.2.41、comfyui-frontend-package 1.58.5 | — |

### 升级 ComfyUI 的坑

github.com 主站当时连不上（codeload / raw / api 反而通）。实际做法：

```powershell
curl.exe -L --retry 5 -o comfyui.zip 'https://codeload.github.com/Comfy-Org/ComfyUI/zip/refs/tags/v0.45.0'
# 解压到工作区后逐文件覆盖安装目录（保留 models / custom_nodes / user）
Get-ChildItem $src -Recurse -File | % { [System.IO.File]::Copy($_.FullName, $dst, $true) }
```

**没有留下任何孤儿文件**——升级后比对"安装目录有的 .py"和"0.45.0 有的 .py"，差集里只有
ComfyUI-GGUF 插件自己的文件，核心是干净的。

### ComfyUI-GGUF 的远端

插件页面上写的 `city96` 是错的，实际远端是 **`github.com/leejet/ComfyUI-GGUF`**，
`git fetch` 反而能用，已快进到最新提交。

## 2. 权重

| 文件 | 目录 | 字节数 | 来源 |
|---|---|---|---|
| `MiniMax-H3-Image-Pruned-Q3_K_M.gguf` | `models/unet/` | 8,911,771,264 | Abiray/MiniMax-H3-Image-GGUF |
| `qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors` | `models/text_encoders/` | 15,687,142,551 | Comfy-Org/MiniMax-H3 |
| `minimax_h3_image_vae_fp16.safetensors` | `models/vae/` | 1,168,505,312 | Comfy-Org/MiniMax-H3-Image |

`scripts/fetch_weights.ps1` 会按精确字节数校验，下载不完整会当场报错。

> **不要用旧版 GGUF 文本编码器**（`qwen3vl_32b_minimax_h3-Q2_K_M.gguf`）：
> 它**没有写架构元数据**（kv=0），ComfyUI-GGUF 认不出来，会报
> `ValueError: This gguf file is incompatible with llama.cpp!`。
> 新转的 Q4_K_M 才有 `general.architecture=qwen3vl`。
> 本机直接用官方 NVFP4 safetensors 绕过。

### GGUF 元数据说明

- `general.architecture` 写的是 **`wan`**：只是复用了 Wan 的结构外壳，
  核心靠张量名识别——`video_patch_proj.weight` + `condition_proj.weight`（无音频分支）
  → `minimax_h3_image`（见 `comfy/model_detection.py:401-412`）。
- **PDD 六步调度靠 GGUF 内嵌的 `config` 元数据传递**：新版插件会自动透传
  （`nodes.py:174`），核心的 `detect_unet_config` 再读出来。
- 实测加载日志：`gguf qtypes: F32 (320), Q3_K (208)`。

## 3. 启动参数

```bat
python ComfyUI\main.py --windows-standalone-build --reserve-vram 1.0 --lowvram --fast-disk --mmap-torch-files --preview-method none --port 8188
```

| 参数 | 作用 |
|---|---|
| `--lowvram` + `--reserve-vram 1.0` | 给 8GB 显存留余量，DiT 放不下就卸载到内存 |
| `--fast-disk` + `--mmap-torch-files` | 14.61GB 的 CPU 编码器靠 NVMe 分页托底（内存不够时靠磁盘换） |
| `--preview-method none` | 省掉预览图的额外采样开销 |

**日志要看到这些**：

```
Requested to load MiniMaxH3Image
gguf qtypes: F32 (320), Q3_K (208)
loaded partially; 5212.80 MB usable, 5140.45 MB loaded, 1711.55 MB offloaded
```

## 4. 采样参数（不可改）

```
sampler = euler    scheduler = simple    steps = 6    cfg = 1    denoise = 1
```

原因见 [`编辑原理.md`](编辑原理.md) 第 6 节：PDD 头组按网格区间加权，步数变了权重就错位。
唯一安全的替代是 `euler` + `sgm_uniform`。

## 5. 画布

- 有效区间 **4–20MP**，理想值在 **16MP** 附近（官方：4096×4096 / 5472×3072 / 6272×2688 …）
- 本机上限 **4MP**（2048×2048），16MP 要 80GB 级显存
- **低于 4MP 模型自己就发糊**，这条比量化档位更硬

## 7. 踩过的坑

- **旧版 GGUF 编码器 "incompatible with llama.cpp"** → 换官方 NVFP4 safetensors。
- **升级 ComfyUI 不能 `git pull`**（github.com 主站不通）→ codeload zip + 逐文件覆盖。
- **ComfyUI-GGUF 远端是 leejet 不是 city96**。
- **GGUF 的 `general.architecture=wan` 属正常**，靠张量名识别。
- **ComfyUI 缩略预览掩盖画质问题** → 判断画质一律看 1:1 裁切。
- **Windows 上 `rm` 是 `Remove-Item` 的别名**，会被安全层拦；
  可恢复删除用 `C:\Users\<you>\.minimax\bin\mavis-trash.cmd "<path>"`，
  注意它进的是 **Windows 回收站**，占着磁盘不释放，要 `Clear-RecycleBin -Force` 才真正腾出空间。
