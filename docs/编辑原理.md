# H3-Image 参考图编辑是怎么工作的（编辑原理）

本文全部结论来自 ComfyUI v0.45.0 源码，行号可直接对照
`ComfyUI/` 目录下的文件核对。

---

## 0. 一句话原理

> **参考图编辑不是 img2img。**
> 参考图被 VAE 编码成**干净的潜变量**，作为一段**不会被加噪、不会被去噪**的 token，
> 拼进文本 token 和目标图 token 之间的同一个序列里；
> 目标画布是从零开始生成的，参考图只作为"上下文"影响它。

所以"编辑"实际是**带参考条件的重新生成**，而不是"在原图上加噪再还原"。
这解释了三件事：

1. 为什么提示词必须写清"最终那张图长什么样"——模型不是在做减法，而是在做加法。
2. 为什么保留不住细节就等于没保住——模型没有"原图"可以偷懒复制。
3. 为什么参考图必须放大到 4MP——它是要当**生成依据**用的，不是当背景贴图。

---

## 1. 数据流总览

```
prompt 文本 ─────────────────────────► Qwen3-VL 文本 token
参考图 ─┬─► 缩放到短边 1024 ─► Qwen3-VL 视觉 token（带 "Picture N: " 标签）
        └─► 缩放到短边 1024~2048 ─► VAE 编码 ─► 参考潜变量（干净）

最终 token 序列（同一个序列里，按顺序拼接）：

   [ 文本 token ][ Picture 1: ][视觉token][ Picture 2: ][视觉token] ][ 你的提示词 ]
   [ 参考潜变量 token（干净，不参与去噪） ]
   [ 目标图 token（加噪 → 去噪 → 出图） ]
```

代码路径：

| 环节 | 位置 |
|---|---|
| 组装参考图 | `comfy_extras/nodes_minimax_h3.py:692-708`（`_image_refs`） |
| 条件节点 | `comfy_extras/nodes_minimax_h3.py:711-746`（`MiniMaxH3ImageConditioning`） |
| 文本/视觉 token 化 | `comfy/text_encoders/minimax.py:187-241`（`tokenize_with_weights`） |
| 潜变量挂到 conditioning | `comfy/model_base.py:2276-2278, 2303-2307` |
| 序列布局 | `comfy/ldm/minimax/model.py:383-500`（`PackedLayout`） |
| 干净/目标行掩码 | `comfy/ldm/minimax/model.py:598-607` |

## 2. 参考图被编码了**两次**

`_image_refs`（`nodes_minimax_h3.py:692-708`）对每张参考图做两件事：

```python
vision_images.append(_resize_to(image, vision_size(*size)))   # 短边固定 1024，给 Qwen 看
if vae is not None:
    z = vae.encode(_resize_to(image, vae_size(*size)))        # 短边 1024~2048，给 DiT 看
    refs.append({"kind": "image", "latent_h": ..., "latent_w": ..., "latent": z})
```

两条路的尺寸由两个常量决定（`nodes_minimax_h3.py:40-41`）：

```python
IMAGE_REF_SHORT_EDGE = 1024                # Qwen 视觉侧的短边
IMAGE_REF_VAE_MAX_SHORT_EDGE = 2048       # VAE 潜变量侧的短边上限
```

**注意：参考图不是被拉伸到目标画布尺寸的。** 它保留自己的长宽比，
在 1024–2048 短边范围内缩放，然后在序列里占**自己的一段空间**（自己的空间网格 `r_frame`）。
这跟经典 img2img 把图缩放到目标画布完全不同。

> **实践含义**：目标画布 2048×2048、参考图 1024×1024 时，
> 参考图在序列里约占四分之一的空间权重。参考图分辨率越高，保真度越高，
> 所以喂小图是最容易翻车的操作。

## 3. 参考潜变量为什么"不会被去噪"

`PackedLayout`（`model.py:383-500`）为每一段 token 分配位置编码和**更新掩码**：

```python
img_update.append(torch.zeros(n, dtype=torch.bool))   # 参考行 → False = 不更新
img_update.append(torch.ones(n_video, dtype=torch.bool))  # 目标行 → True = 参与去噪
```

采样时按掩码组装（`model.py:598-607`）：

```python
all_video_rows[~img_update] = cond_video_rows   # 参考潜变量：原样塞进去
all_video_rows[img_update]  = video_rows        # 目标潜变量：被加噪/去噪的那份
```

也就是说，参考图的 VAE 潜变量在 6 个采样步里**一次都不加噪、一次都不被预测覆盖**，
它作为纯上下文参与 attention。位置编码上，参考段占用文本段之后、目标段之前的时间轴
（`cursor` 逐段累加，`model.py:400-443`）。

**这就是"编辑"的全部秘密**：目标图 = 从噪声出发，在（文本 + 参考潜变量）的条件下生成。

## 4. 文本侧：`<Picture N>` 是怎么对上的

`MiniMaxH3ImageConditioning` 调用：

```python
clip.tokenize(prompt, images=vision_images, picture_label="Picture %d: ")
```

`tokenize_with_weights`（`text_encoders/minimax.py:231-236`）：

```python
for i, img in enumerate(images):
    add_text(picture_label % (i + 1))   # "Picture 1: "
    add_vision(img)
add_text(text)                          # 你的提示词排在最后
```

两个要点：

1. **图片标签由代码自动插入**，你不用在提示词里手写 `Picture 1:`。
2. **你的提示词排在所有视觉 token 之后**——模型读图的顺序是"先看图，再听你说要改成什么样"。

而你在提示词里写的 `<Picture 1>` 是**语义指针**：模型在训练时学到了
"提示词里的 `<Picture 1>` 指向标签为 Picture 1 的那张图"。
（H3 视频的 ref 通路用的是带尖括号的 `<Picture %d>: `，H3-Image 这条路是 `Picture %d: `，
`minimax.py:188` 是默认值，`nodes_minimax_h3.py:739` 覆盖成了无尖括号版。）

**多图时编号按 `images` 字典的序号排序**（`nodes_minimax_h3.py:698`）：

```python
names = sorted(images or {}, key=lambda name: int(name.rsplit("_", 1)[-1]))
```

`image_1` 永远是"要编辑的那张"，`image_2` 及以后是"素材图/参考图"。

## 5. 提示词为什么要写成"已扩写版"

官方 H3-Image 有一个专用的 **PE（prompt expander）模型**（`MiniMaxAI/MiniMax-H3-Image-PE`），
它的输出规范被写死在官方工作流模板里（`comfyui_workflow_templates_json/templates/image_minimax_h3_image_edit.json`
的节点 39）。规范要求产出**一段连续的英文散文**，内部是三段式：

| 块 | 内容 |
|---|---|
| Part 1 | 主体定义：`The subject in <Picture 1> is <Subject 1>, <原文可见的特征>` |
| Part 2 | 保留关系：`<Subject 1> is fully preserved.` / `<Subject 1> is partially preserved; ... remains, while ... changes to ...` |
| Part 3 | **只写变化与新增**：变化后的最终形态、新元素、以及落地细节（接触、遮挡、阴影、反光、透视、光照） |

关键硬规则（官方原文）：

- **fully preserved 的主体，之后绝不能再被视觉描述**，只能用裸 `<Subject N>` 当空间锚点。
- Part 3 **不得**重新描述保留部分，也不得为了"像完整描述"去补背景/光线/镜头。
- 描述性文字一律英文；**新写的画面文案**用用户要求的语言并**用单引号包住**。
- 字面文本必须写全，不许 `...` / `etc.`。
- 网格必须写清行列数。

在 `p-h3-image`（PE 变体）那条路上，代码会自动给短指令加前缀（`nodes_minimax_h3.py:45, 780`）：

```python
PH3_IMAGE_EDIT = "Edit <Picture 1>. {}"
PH3_IMAGE_EDIT_VERBATIM = re.compile(r"\s*(Edit <Picture \d+>|subject_definitions:)")
prompt = prompt.strip() if PH3_IMAGE_EDIT_VERBATIM.match(prompt) else PH3_IMAGE_EDIT.format(prompt)
```

即：**短指令会被自动包成 `Edit <Picture 1>. <你的指令>`**；
但如果你写的提示词**已经以 `Edit <Picture N>` 或 `subject_definitions:` 开头，就原样使用**。
后者正是"我已经自己写好扩写版"的标准姿势。

> **本机装不下 PE 模型**（`qwen3.5_9b_w4a8_gptq` 6.84GB，16GB 内存不够），
> 所以扩写这一步必须由你手动完成——直接写三段式的完整描述。
> 详见 [`提示词模板.md`](提示词模板.md)。

## 6. 采样：为什么 6 步、euler、CFG=1 不能动

H3-Image 用的是 **PDD（Parallel/Distilled…）头组**：模型输出层不是单个预测头，
而是 `pdd_steps` 个头的组合，每一步消费它跨过的那几个网格区间（`model.py:349-380`）：

```python
# a step consumes the heads of the grid intervals it spans
start, stop = (... for s in (sigma, sigma_next))
out.append(head(h) if n == 1 else _pdd_head(head, h, grid, start, stop))
```

而 sigma 网格是**按网格下标线性**的（`comfy/ldm/minimax/sampling.py:6-25`）：

```python
class MiniMaxH3ImageModelSampling(comfy.model_sampling.ModelSamplingDiscreteFlow, comfy.model_sampling.CONST):
    """Flow sampling on the PDD sigma grid of a MiniMax-H3-Image checkpoint.
    sigma() is linear in the grid index, so the stock schedulers at pdd_steps steps
    land on the grid the heads were distilled for; the flow shift is unused."""
```

结论：

- **步数必须等于 `pdd_steps`（=6）**，否则每一步跨过的网格区间和头组合对不上，
  输出就是"错位加权"的垃圾。
- **调度器换成 `sgm_uniform` 是安全的**（同样落在网格点上），换 `karras`/`exponential` 就未必。
- **CFG 固定 1**：这是蒸馏模型，没有 CFG 分支；负面提示词走 `ConditioningZeroOut`（置零），
  CFG=1 时根本不参与计算。所以**写不写负面提示词都一样**。
- `denoise` 固定 1：这是"从零生成"，不是 img2img 的局部重绘。

## 7. 量化对"编辑保真度"的影响

参考图在序列里是**干净的 VAE 潜变量**，它不是像素，所以量化影响的是两处：

1. **DiT 权重**：DiT 负责"读懂"参考潜变量并据此生成。2bit 下 DiT 自己也糊，
   对参考图的理解能力下降 → 编辑结果保不住细节。
2. **VAE 权重**：VAE 负责把参考图编码成潜变量。VAE 是 fp16 官方版，没被量化，所以这一路是干净的。

实测结论（同提示词、同种子、同参数，只换 DiT 量化档）：

| | Q2_K (2bit) | Q3_K_M (3bit) |
|---|---|---|
| 玻璃窗棂 | 糊成一片 | 一根一根立得住 |
| 黑板字迹 | 无法辨认 | 笔触清晰（仍是伪文字，模型上限） |
| 面包 | 边缘糊成块 | 每只独立、带烘焙裂纹 |

> 同 seed 在不同量化权重下**构图也会变**（潜变量轨迹不同），这是画质对比而非像素差分。

## 8. 实践清单

1. 参考图**先放大到 4MP**（短边 1024–2048 区间内），小图必糊。
2. 目标画布 **≥4MP**，且边长是 32 的倍数。
3. 提示词写成**三段式完整描述**，不是短指令。
4. `<Picture N>` 只按 `image_N` 的序号引用；`image_1` 是被编辑的那张。
5. **不要重复描述**标为 fully preserved 的主体。
6. 一次只改 1~2 件事。
7. 采样参数锁死 `euler / simple / 6 / CFG 1 / denoise 1`。
8. 判断画质**一律看 1:1 裁切**，不要看 ComfyUI 的缩略预览。
